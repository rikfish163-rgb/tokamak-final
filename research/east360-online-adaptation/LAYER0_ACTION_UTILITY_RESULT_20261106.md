# 炮内更新的瓶颈：历史缺少可学的纠错样本，已有动作也救不回大多数漏报

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: run
- Origin Date: 2026-11-06
- Verification Status: 原 HDF5 独立重核、原拟合逐参数复现、真实混合写入对照通过
- Version Label: layer0_action_utility_v1（历史生产为 v2）

**结论。** 继续训练一个“放行现有动作”的门控不是当前最优先的方向。原历史标签在逐炮留出后几乎没有提供可学习的首报收益；即使事后每个更新区间都能从现有动作里选最优，两个开发队列的检出仍有明显上限。下一步应先验证是否存在同幅度、却能覆盖漏报轨迹的内部更新方向，再谈如何从未标注的当前炮中选方向。

## 1. 已揭示历史：同一段信号，切换一个内部更新会发生什么

统一使用冻结 J-TEXT Transformer 和 EAST 的原阈值、采样时钟与 HDF5 结局。冷启动 20 炮（8 破裂、12 安全）逐炮留出；每折的 EAST 数值映射及初始拟合、三轮高风险安全窗口再拟合均只用其余 19 炮，整个生成器从头训练。被留出的炮不参与自己那折的信号统计或标签拟合。这里是冷启动标签已揭示后的教学诊断，不改写原来前 20 炮的静态预测，也不是冷启动第一炮就能用的模型。

同一历史协议后来封存后查询的 16 炮（4 破裂、12 安全）沿用锁定的冷 20 生成器；两条曲线均与原归档逐点相同。各查询记录绑定了原块提交、标签读取及生效秩。这里没有用 360 或 835 的额外评分标签训练筛选器。

每 32 个采样点为一个可换的动作区间。同炮同信号有三种反事实：在全静态背景里只写入这一步；在全更新背景里只撤回这一步；从左到右逐块用真实更新替换静态，比较每步新增或失去的首报效用。第三种把贡献精确加总回整炮差；其余两种用于区分单步足够、多个区间可替代和多个区间共同消除误报。对破裂炮，首报 `30 < lead ≤ 3000 ms` 为有效，另报 `lead > 30 ms`；对安全炮，任何首报均为误报。

| 历史样本 | 单块就有益的不同炮 | 单块就有害的不同炮 | 逐块累积时曾有益／有害的不同炮 |
| --- | ---: | ---: | ---: |
| 冷 20，逐炮留出 | 0 | 1 | 0／1 |
| 原 16 查询 | 2 | 3 | 3／3 |

冷组的 38 个有害单块全来自同一个安全炮 `70323`，不是 38 个独立例子。冷组合理提前量同为 5/8，误报由 0 增为 1。查询组中，单块救回的两炮是 `69791`、`85023`，单块造成误报的是 `82834`、`60239`、`64562`；`67900` 则需要多个区间共同作用，才能消除误报。原查询组刻意富集接近报警分歧的炮，不用其 FPR 或 TPR 估计全流。

因此两个预设覆盖门槛均未通过（冷 20 两类各至少 5 炮、原查询 16 两类各至少 3 炮）。**没有拟合读出模型，也没有宣布轨迹不可辨。** 结论是这批历史在现有更新机制下不支持该读出的训练与验证，不能靠重采同一炮的窗口掩盖缺口。

## 2. 后验选对每一步，现有动作最多能做到什么

对每个区间只允许从当时的零动作、原真实炮内动作中选一个；扩展对照另外允许两种已有投影。原模型的下一次候选动作从冻结主干的原始前缀计算，不读取先前动作改写的表示，所以可以组合各臂的实际前向曲线。某一区间如果所有可选动作都先报警，就无法跳过它去取得更晚的首报；而第一次适配前的公共首报永远不能撤销。枚举给的是该有限动作菜单的**精确回顾上限**，不是新在线策略、不是同一层任意参数的理论上界。

| 回放 | 方法 | 严格及时 `>30 ms` | 合理提前量 `30–3000 ms` | 安全误报 |
| --- | --- | ---: | ---: | ---: |
| 固定 360（180D／180S） | 静态 | 116 | 100 | 29 |
| | 原炮内 | 120 | 105 | 33 |
| | 后验：静态或原炮内 | 122 | 110 | 28 |
| | 后验：再允许两种投影 | 122 | 110 | 28 |
| 额外 835（510D／325S） | 静态 | 257 | 203 | 68 |
| | 原炮内 | 299 | 235 | 85 |
| | 后验：静态或原炮内 | 305 | 250 | 58 |
| | 后验：再允许两种投影 | 305 | 251 | 56 |

两列“及时”分别最优化，并不保证同一套逐区间选择同时取得两列最大值；由于炮间无状态更新，破裂炮最高检出与安全炮最低误报可以在各自同一口径下同时达到。835 中扩展后验最高合理提前量是 251/510（49.22%），最低 FPR 是 56/325（17.23%）；比二选一只多一炮有效预警、少两炮误报，不能把更多投影形态当成新表示的替代品。

额外 835 上，静态未达到合理提前量的 307 个破裂炮中：**217 炮在合格时间区间内没有任何现有动作能越阈**，42 炮虽然有合格越阈点，但无法让它成为首报，剩下 48 炮才是扩展菜单理论上能救回的对象。360 的对应分解为 59／11／10。对 217 炮，后验门控也无从选择；若仍冻结基模与阈值，必须找到真正新增的内部更新方向。两组队列均参与过开发；额外队列与 360 不重叠，但不是独立未来流。

## 3. 核验和下一步

- 历史 CUDA 初版在映射预检停止，未执行拟合。原因是拟合统计前漏掉原流程的 CIII 缺测掩码，已加回归测试，保留失败目录。修正后 v2 用 `rl_env` CUDA 完整跑 36 炮（会话 83111，退出码 0，43.51 s）；全 20 历史映射与原档案完全相同。额外全 20 重训逐参数重现原生成器，最大差为 0。
- CPU 历史核验（29323）重读 36 炮 HDF5，检查 20 折排除角色、16 炮原封存复现及 120 个真实拼接位点；CPU 上限核验（93837）重读 1,195 炮原始时钟和结局，均退出 0。CUDA 真写入见证（21890）在 6 炮交替施加四种动作，两种混合顺序共 12 条曲线，与逐区间拼接越阈完全一致，最大概率差 `1.79e-7`。265 项相关测试通过，未测装置实时延迟。Terra/max Franklin 实现 CPU 反事实内核和穷举测试；主进程完成实跑和验收。
- 已直接核对生成器第一层输出矩阵：从 32 维隐藏状态映射到 128 维缩放／偏移，连偏置张成的线性空间为 33 维；有界缩放不会增加维数。这个事实本身不证明受限方向是失败原因。下一实验以同一写入点、同范数，实测原空间内梯度、原空间外梯度与任意同幅方向能否补上缺失的及时越阈。若空间外仍救不回来，优先改作用位置或时序表示，不再继续训练当前门控。若可以救回，才用已结束轨迹学习如何预测这个方向，而不把风险梯度的正负真值带进当前炮。
