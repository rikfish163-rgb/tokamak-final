# J-TEXT event labels: what they supervise and one offline temporal-feature test

## Material Passport

- Date: 2026-11-03. Scope: local evidence and an experiment proposal for EAST intra-shot research. No external sources were consulted.
- Origin: academic-research-suite / experiment-agent, and a scoped data-quality review.
- Status: **READ-ONLY EVIDENCE AUDIT; EXPERIMENT PROPOSED, NOT RUN.** Existing results below are historical artifacts, not new runs. This review did not use a GPU or run a J-TEXT online branch.
- The qualified source checkpoint was independently SHA-256 checked as `c7270c1ea3652db2e30e972d4ca9a4a2d33220a68e4a3765c8b7f5bcceeaeb02`. No model or experiment file was modified.

## Decision in brief

The supplemental file supplies **offline candidate event intervals**, not a per-time danger, recovery, or physical-mode truth. A defensible next test is to use its interval identities to select within-event pairs of **frozen-source temporal features**, teach a small order-sensitive auxiliary loss offline, and test whether one temporary internal update improves later risk in the existing fixed source episodes. No event identity is needed at EAST runtime, and the auxiliary score is never added to the risk score. This tests a different use of intervals from the already-run six-family context routers; it is not evidence that the idea works, nor a claim that a similar idea is new.

The source-event classifier already distinguishes families on annotated source validation intervals, but both the ensuing source event-conditioned update rule and the separate held-EAST20 channel-policy screen failed their respective gates. Its input was a past-window signal summary, not the source's Transformer tokens; its classification result therefore does not establish that frozen temporal tokens carry the same information. A previous source-trained temporal-order auxiliary also failed to improve the complete EAST360 alarm counts, so a new interval-selected temporal objective must beat its own controls rather than inherit credit for learning temporal order.

## 1. What the file actually contains

The original [UTF-8-BOM CSV header and examples](references/JTEXT_event_labels.csv#L1) contain exactly eight fields. The supplier's [field definitions](references/字段说明.txt#L11) distinguish the grains:

| Field | Grain and legal interpretation |
|---|---|
| `shot_no`, `cohort`, `disruption_label` | Shot-level identity, annotation-project cohort, and final binary shot outcome. The outcome is repeated on event rows; it is **not** a pointwise event danger label. |
| `event_index`, `event_class`, `event_start_s`, `event_end_s` | Per exported final event, chronological index within shot, nominal class A–F, and boundaries on the **absolute original diagnostic clock**. One shot may have several rows/events. |
| `annotation_status` | `event`: the four event fields are populated; `no_event_detected`: processed, no final event retained; `excluded_short_record`: under 50 ms and not annotated. The latter two have blank event fields. |

The exported segment is `[start,end)`, with boundaries at `0.15 + 0.005 × token_index` seconds; this 5 ms export grid is not a validated boundary-error interval. The HDF5 `ip` data used here are 1 kHz, so its 1 ms samples must be aligned to that absolute clock, not to time-to-disruption or to zero-based elapsed seconds. The interval endpoints are merged offline labels, **not** original MIL onset points, online confirmation times, or demonstrated recovery boundaries. [Timing/status contract](references/字段说明.txt#L21); [existing absolute-clock assignment](experiments/risk_aligned_online/event_prefix_probe.py#L41).

The six names below are descriptive **candidate signal groupings** from the supplied explanation, not adjudicated physical events or ordered severity levels. The letter naming used developmental median lead times; it does not imply A→F progression. In particular, classes occur in both final outcomes. [Supplier descriptions](references/字段说明.txt#L44), [ordering and provenance limits](references/字段说明.txt#L93).

| Family | Supplied descriptive shorthand | All exported events | Source TRAIN events | Source VAL events |
|---|---|---:|---:|---:|
| A | displacement-related | 40 | 19 | 6 |
| B | mode/frequency-related | 27 | 16 | 6 |
| C | horizontal displacement / lower magnetic-amplitude features | 218 | 146 | 23 |
| D | elevated magnetic-disturbance features | 317 | 170 | 57 |
| E | CIII profile/emission features | 85 | 21 | 12 |
| F | SXR / radiation-profile features | 45 | 29 | 8 |

These are **event counts**, not independent-shot counts; family rows can contain multiple events from one shot. The raw CSV independently counted 1,975 data rows, 1,816 unique shots, 732 events on 573 shots, 1,234 `no_event_detected` shots, and nine short-record exclusions. Source TRAIN contains 327 event shots / 401 events out of 1,353 shots; VAL contains 83 / 112 out of 160; TEST contains 122 / 166 out of 220. The other 83 export shots include 53 events, all A or E, and have no current canonical local HDF5 path. Thus the 1,733 existing source-role HDF5 paths correspond to 679 event rows on 532 event shots; the 53 extra events cannot be treated as current waveform examples. Source split IDs were taken from the [canonical role index](references/index.json#L17814), as used by [the source reader](experiments/risk_aligned_online/io23.py#L119).

**Unknown is not negative.** `no_event_detected`, excluded records, gaps, and times outside exported intervals do not prove normality or absence of an event. The existing parser represents an unassigned sample by `-1`, not an invented normal class. The old source risk label is a separate point target derived from the shot outcome and disruption time with horizon `max(25 ms, AdvancedTime)`; a disruptive query is eligible only at lead `>10 ms`. That operational definition is neither an event boundary nor a physical onset. [Parser](experiments/risk_aligned_online/event_prefix_probe.py#L64); [source horizon and query checks](experiments/risk_aligned_online/source_event_tasks_20261102/data.py#L42).

Permissible offline targets include: conditional family classification **only on known intervals**; same exported-event membership at two known endpoints; chronological ordering of observed pairs selected using interval IDs; and a separately defined source point-risk target using HDF5 disruption time and the existing horizon. The last is derived, not supplied by the event CSV. It is not valid to label every time in a disruptive shot dangerous, every gap normal, event end as recovery, A–F as ordinal risk, or an unobserved EAST event family as ground truth. If a pair crosses two labeled intervals, their distinct IDs are known; the intervening gap still has unknown status, so that is not automatically a continuously observed state transition.

The source teacher and vocabulary used whole-record offline analysis and overlap historical source splits: simply training a new head on TRAIN does not make VAL or TEST independent of the upstream label-generation process. A prior audit found 202/220 source TEST shots in the event project's training pool. The prior package also lacked enough upstream code and model artifacts to reproduce the generator. [Prior local linkage and split audit](references/数据价值分析.md#L92).

## 2. Existing attempts: what was actually tested

1. **`source_event_context_paired_v1`.** The paired heads share initialization, minibatch indices, feature selector, optimizer budget, and TRAIN pool; whole-event labels are shuffled in declared strata for the control. Their 115-dimensional past-window signal summary retains variation/availability blocks and masks MNM; it is **not** a Transformer-token feature. On annotated VAL intervals, event-weighted macro-F1 was **0.679357 true vs 0.231646 shuffled**. This is conditional family classification on 83 shots / 112 events / 2,598 endpoints, not event detection or an EAST alarm metric. The archived cache contains TEST bytes, although its protocol says TEST was not used for fitting, prediction, or scoring. [Paired training implementation](experiments/risk_aligned_online/source_event_tasks_20261102/context_pair.py#L41); [feature selector](experiments/risk_aligned_online/event_conditional_feedback_20261102/context.py#L11); [VAL result](probe_outputs/source_event_context_paired_v1/validation.json#L1); [archive exposure statement](probe_outputs/source_event_context_paired_v1/protocol.json#L92).
2. **`source_event_tasks_20261102` / `source_event_masked_tasks_v1`.** The frozen source, paired event heads and same event-stratified sample schedule taught 575-parameter shared or 3,450-parameter event-conditioned diagnostic update tables. On VAL with MNM+CIII masked, true-event real-feedback ΔBCE was −0.030757 for safe and **+0.065679** for danger; the latter worsened in 96/117 queries. The balanced ΔBCE, +0.017461, was worse than shared, shuffled, and reverse. This was a failed source-local gate, not an EAST TPR/FPR result; even the shared arm used event stratification. [Implementation and objective](experiments/risk_aligned_online/source_event_tasks_20261102/trial.py#L234); [saved VAL summary](probe_outputs/source_event_masked_tasks_v1/validation_summary.json#L438).
3. **`conditional_channel_policy20_v1`.** It reused the paired source heads at the origin to learn a 23-channel policy from existing EAST20 gradient contributions. The held-fold true arm's mean change in the linear proxy was −0.000436 safe but +0.000899 in the 30–125 ms danger group; its saved gate failed against global, shuffled, reverse and hold. This is a **first-order shared-cap direction screen**, not a recomputed finite neural update or online alarm test. The parent/cold state had already seen these 20 shots, so the holdout is only for the added controller. [Actual source-head linkage](experiments/risk_aligned_online/conditional_channel_policy_20261102/prepare.py#L20); [linear limitation](experiments/risk_aligned_online/conditional_channel_policy_20261102/core.py#L1); [saved gate](probe_outputs/conditional_channel_policy20_v1/completed.json#L1).
4. **Other temporal/event work is also prior evidence.** A source-trained order task on rearranged chunks learned its auxiliary discrimination, yet all four tested EAST360 arms had identical 125 TP / 32 FP; its auxiliary updates did not establish useful risk direction. An earlier same-shot ranking approach used *EAST historical early/late risk labels*, not the proposed source same-exported-event feature pairs, and missed its own TP-protection gate. An earlier source event-teaching ablation showed family recognition could largely occur without its fast state. [Order experiment](references/时间顺序辅助任务_完整360与更新方向失配_20261029.md#L8); [historical-pair experiment](references/同炮前后配对_事前约定_20261024.md#L18); [event/fast ablation](references/事件教学_源域机制诊断与续跑_20261027.md#L11).

## 3. Feasibility census for the proposed pair construction

I independently read the original CSV, source role IDs and the *existing* `shot_linkage.csv` metadata, not signal arrays. For every TRAIN/VAL event: use 1 ms HDF5 sample indices `i≥127`; require `t_i` and `t_(i+25)` to lie in the **same** exported interval, require a real `i+26` sample, and for disruptive shots require its lead to be strictly `>10 ms`. From each event's eligible ordered indices select unique positions `floor(k*n/5)` for `k=1,2,3,4` (clamped at `n−1`). This yields at most four pairs/event. The `i+26` groups below use the existing source point-risk contract, not the shot outcome as a per-event label; the same groups are used retrospectively for matching, never as model inputs.

| Population, before matching | Events | Shots | Pairs | Safe pairs / shots | Danger pairs / shots | Early disruptive pairs / shots |
|---|---:|---:|---:|---:|---:|---:|
| TRAIN | 241 | 231 | 958 | 460 / 112 | 111 / 55 | 387 / 108 |
| VAL | 72 | 64 | 285 | 20 / 5 | 97 / 38 | 168 / 50 |

An early and a danger pair can come from the same disruptive shot; do not add shot counts across groups. To make a concrete comparator, for each chosen pair find the nearest other origin `j` within ±50 samples on the **same shot**, breaking equal-distance ties toward the earlier index. Require `j≥127`, `j+26` in record, the same source query group and, for disruptive shots, the same strict lead condition. For the comparator, `j` and `j+25` must **not both belong to any one exported event**. Retain an event pair only when this match exists, in *both* arms. This is an annotation-informed sampling control, not a claim that the comparator is normal or event-free.

These are **not** independent windows, a completed training set, or model results. The matching census does not check every channel's finite availability or load feature values; the proposed execution must recheck masks and report any exclusions. In particular, the matched TRAIN near-danger examples involve only 10 shots and the VAL safe examples only five: the matched pairs alone cannot support a strong safety or generalization claim. The main risk screen below therefore also uses the previously fixed full VAL episode archive and reports known/unknown origin separately. It does not turn unknown into a class.

The fixed source-task VAL archive has 946 episodes from 145 shots: 638 safe / 80 shots, 117 danger / 64 shots and 191 early / 51 shots. Of the safe origins, 618/638 are unknown. The counts are archived and are not comparable to the matched-pair counts above. [Census](probe_outputs/source_event_masked_tasks_v1/census.json#L233). ## 4. One minimal next experiment: interval-selected temporal-order loss

**Question.** When the qualified source is held fixed, can order supervision selected by an exported event interval produce an auxiliary gradient whose actual internal update helps later source risk, beyond matching the same shots and learning an arbitrary temporal direction? The alternative is explicitly allowed: the auxiliary task can improve while later risk worsens, as previously observed.

**Inputs and frozen path.** Train only on the matched TRAIN pairs above; keep all VAL shots held for the added auxiliary head. Use the established source `c727…` with its source slow state zero, source input mapping and risk head frozen. Use the existing first-FFN rank-4 basis and a zero-start temporary `4×64` state `δ`; do not duplicate the main anchored-forecast implementation. The existing [source-native basis](experiments/risk_aligned_online/adaptivity_capacity_20261102/model.py#L11) and [internal, not score-level, insertion](experiments/risk_aligned_online/lora_stream_20261102/core.py#L78) show the intended parameter location. Source weights, source normalization and risk head are never trained.

For each observed 128-point causal window at `t`, let `z_t(δ)` concatenate the mean of the valid 16 data tokens and the last valid data token after the first FFN, using the same fixed 64-dimensional source-token representation in both halves. If either TRAIN pair has no valid data token, exclude its matched pair in **every** arm. At evaluation, retain every archived episode; when either window has no valid data token, make every arm a no-update case and report it. Do not provide the head with shot number, absolute clock, interval start/end, event age/duration, family, outcome, future samples, or ground-truth risk. Use the existing input/availability contract; train with MNM+CIII masked, while also evaluating the native view. Estimate per-coordinate standard deviations on TRAIN only, floor them at `1e-6`, and use the identical frozen transform in every arm. The two 128-point windows overlap by 103 samples: a ramp, missingness pattern, or sliding-window artifact could solve the auxiliary task without capturing a useful event evolution.

**Teach an auxiliary temporal loss offline.** On each matched true interval pair, with the source and `δ=0` frozen, form `d=z_(t+25)−z_t`. Fit one bias-free 128→1 linear vector `w` by `softplus(−wᵀd)`; the reversed ordering has the opposite target, and `wᵀd` is **only an auxiliary order score**. Sample shot first, then event, then pair, all uniformly, using one fixed TRAIN schedule; fit 512 AdamW steps, batch 64, learning rate 0.001, weight decay 0.001, seed 131, final iterate only. Family and outcome may define the offline balanced permutation strata below, but never model inputs. Do not fit using VAL or EAST. Save the actual matched identities, masks, counts, schedule and source/teacher hashes; if matching or nonempty masks cannot be reproduced, stop instead of silently substituting data.

**Controls, fixed in advance.**

- `true_order`: train on the matched within-event pairs with their real order.
- `shuffled_order`: same pair inputs, initialization, minibatch identities and budget, but flip the chronological training sign for a fixed approximately half of whole events, balanced where possible within TRAIN family × shot-outcome strata; use a declared fallback to shot-outcome strata for singleton cells. This tests the order target, not family classification. Keep every event's multiple pairs together.
- `matched_other_order`: use the nearest matched comparator pairs defined in §3 with the real chronological target, the same source shots, matched query group, capacity, seed and training budget. This assesses **interval-based selection**, not “event labels versus no labels”: the comparator construction itself consulted interval boundaries. Report its actual event overlap and exclusions.
- `no_update` and `reverse_update`: at evaluation use zero `δ` or the opposite chronological target, `softplus(+wᵀd)`, respectively. Normalize nonzero gradients to the same state-step norm, so a difference is not merely a larger step. A zero-gradient arm must remain zero and be counted, not normalized into a fabricated direction.

**Offline one-step diagnostic, not J-TEXT online.** For each saved source VAL episode, start `δ=0`; after both windows through `t+25` have arrived, compute `g=∂ softplus(−wᵀ[z_(t+25)(δ)−z_t(δ)])/∂δ` and set `δ′=−0.1 g/||g||` for nonzero `g`. Apply the existing per-window internal-shift RMS cap of 0.25; no acceptance decision uses risk or labels. Evaluate the original frozen risk head at the already archived later `query` (`t+26…t+50`), once with zero state and once with `δ′`, and discard `δ′` after this single episode. Use `softplus(+wᵀd)` for `reverse_update`; use the same inputs, step norm, cap and query for all arms. Recomputing a past-window representation for this gradient does not rewrite a previously issued prediction. The update itself has no access to query outcome, although the retrospective dataset construction and later scoring use outcomes. No state is carried between J-TEXT episodes and no J-TEXT online stream is run.

Computing this auxiliary loss requires only the chronological order of two arrived windows, not a J-TEXT event label. It can nevertheless push representations in an unhelpful direction, especially at unknown intervals or true transitions; the test below is intended to reject that behavior, not assume it away. The score `wᵀd` is never added to, subtracted from, or used to recalibrate the final risk. No family probability routes updates.

**Falsification and stop.** First verify zero-state source parity, identical paired inputs/schedules, frozen hashes, nonzero finite derivatives into the actual `4×64` state, and agreement of cached and direct first-FFN insertion on predeclared examples. Report order discrimination by shot and by event, with correct vs shuffled teacher, as a diagnostic only. For each mask view, score `ΔBCE=BCE_after−BCE_zero` on the **same** 946 fixed VAL episodes: average within shot, then within safe, danger and early groups. Before any run, require true-order ΔBCE < −1e−6 separately for safe and danger, early ΔBCE ≤ +1e−6, and the equal safe/danger mean at least 1e−6 below every matched-other, shuffled-order and reverse-update control. Also report every group's shot/episode counts, all per-shot signs, known vs unknown origin, and zero-gradient counts. If any required group is absent, parity/causality fails, or any condition fails, reject this candidate; do not search steps, masks, or thresholds on VAL. These numeric margins are deterministic engineering gates, not significance or clinical/physical thresholds.

Only if that entire source screen passes should the main process consider the **same frozen teacher and update**, without refitting, on its already-fixed EAST20 causal episodes; apply EAST's existing point-label/lead contract only after prediction for evaluation, compare the same controls and use the unchanged cold parent, threshold, input map and original risk head. EAST has no event labels in the update. This is at most a previously exposed-development pilot, not independent confirmation or a new full-stream TPR/FPR. A later prequential stream would still be a separate authorized decision.
