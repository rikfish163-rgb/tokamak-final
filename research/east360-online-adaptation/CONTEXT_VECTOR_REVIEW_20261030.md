## Bottom line

The specified finite inner step and outer gradient are connected correctly in the inspected teaching code. I found **no demonstrated autograd disconnection, record-order mismatch, or query-before-maturity violation** in this screen. There are genuine structural limits on what feedback can express, plus several control and causal-interface qualifications below. These are distinct from the observed empirical failure: `probe_outputs/context_vector_cold20_v1/complete.json` reports `full_stream_gate=false`, because timely-danger real-feedback BCE did not beat the three prescribed controls. The result does not establish that the model ignores feedback or that it improves operational alarms.

## Gradient and representation findings

1. **Finite-step path is connected, including through clipping.** `context_vector_20261030/prepare.py:32-36,43-64` computes the origin first layer from an 8192-dimensional zero Q/K state, uses the same computed `h[:, -1].detach()` as reference, sets `create_graph=True` for training, and passes the resulting step into the later-query forward. `attention_lowrank_20261029/model.py:31-49,55-65` applies the two state matrices to first-layer Q and K in both forwards. The frozen network is not itself trained. For origin Jacobian `J_o` and target `v`, before clipping the actual step is `s = 0.1 J_o^T v`; the outer loss is evaluated by a fresh nonlinear query forward at `s`, not by a cached first-order risk estimate. On a two-row CPU float64 synthetic model, directional finite differences agreed with outer autograd to relative error `7.2e-10` for an **unclipped** step (norms 0.00318 and 0.00291) and `2.5e-9` for an **actively clipped** step (norm 0.1). This is a local numerical check, not a proof for all data or CUDA.

2. **Structural expressivity limit, not a broken gradient.** `learning.py:72-110` targets only the 64-dimensional origin CLS representation. Thus every unprojected Q/K step lies in the image of `J_o^T`, with rank at most 64 out of 8192; radial clipping keeps the same span. A later-query loss gradient orthogonal to that image supplies zero controller gradient through this update, regardless of network size or feedback quality. When clipping is active, radial sensitivity is also removed locally. A same-origin full-model risk-gradient direction need not lie in this reachable subspace, so its result is a useful competing direction, not a like-for-like representability test.

3. **Temporal resolution is structurally limited.** `learning.py:40-47` reduces each consecutive five-point block to per-channel means and availability counts. Any within-block permutation of value/mask pairs is mathematically invisible to the controller, apart from floating-point summation roundoff; in a CPU check the maximum context difference was `5.6e-17`. The five blocks retain their coarse order, but a failed reverse control cannot by itself prove failure to learn finer order that the representation has already discarded.

4. **Zero initialization is correct but delays early-layer learning.** `learning.py:54-69` zeroes the last linear layer. At initialization the step is exactly zero when the reference is the same `h`, while first-layer/LayerNorm controller parameter gradients are necessarily zero; the final layer can receive nonzero outer gradients. My synthetic check saw zero gradients for the first four parameter tensors and nonzero gradients for both final-layer tensors. This is expected, not a defect; if final-layer gradients cancel or vanish, however, the other layers cannot start learning. `representation_step(..., create_graph=False)` is intentionally the default: with the frozen query model it disconnects the controller from the outer loss. The current fitting call correctly overrides it (`prepare.py:36,56`); evaluation deliberately does not need that graph.

5. **Reference and no-support hazards are conditional, not observed failures here.** `observation.py:16-17,29-31` returns a separately computed reference; `learning.py:98-101` permits an unequal supplied reference. With `v=0`, a mismatched reference still produces a nonzero step. A CPU toy check with an anchor offset of `1e-4` produced step norm `1e-5`; the same-forward anchor was exactly zero. The current `prepare.py:34-36` and `smoke.py:64-66` avoid this by recomputing the anchor from the same forward. Also, a zero update proposal on completely missing feedback is not automatically a no-op for a previously nonzero active state if a future stream runner **replaces** it with zero; skipping the update versus explicitly resetting to cold must be decided and reported. No such stream runner was reviewed here.

## Causality, alignment and controls

6. **The inspected screen respects the sampled timing, but is retrospective.** `observation.py:9-29` reads the origin window and the subsequent 25 arrived samples; the function itself has no as-of clock argument, so the caller must enforce maturity. `prepare.py:197-203` checks `maturity=origin+25 < query <= origin+50` and recomputes disruption lead from file times with strict `>30 ms` and `<=125 ms` for positives. An independent CPU comparison against cold20 HDF5 outcomes and the stored rate/start metadata found zero flag, point-label, maturity, late-query or query-bound mismatches across 688 records. This does not establish causal behavior in a future streaming caller.

   The archived query is selected by the frozen parent's maximum risk among eligible points in the later 25-point interval (`operational_transport_20261030/prepare.py:39-52,114-130`). That is an offline, outcome-conditional component screen at retrospectively selected query times, not a prequential full-stream alarm evaluation. A disruptive record whose selected peak is earlier than 125 ms is excluded from supervised training even if another candidate point might fall in the positive interval. This selection is not a future-input leak into the controller, but it restricts the estimand.

7. **Record-to-tensor alignment and supervision check out on the inspected archive.** `prepare.py:190-212` iterates shots in `ids` order and records in original order within each shot, then checks the grouped shot sequence; the archive passed an independent object-order check and had no duplicate `(shot, origin)` pairs. `teaching.py:7-10` and `prepare.py:219-224` select 105 safe rows and 71 timely-positive disruptive rows; the other 512 disruptive rows do not enter the supervised objective. Mini-batch weights index the same local permutation as the selected data (`prepare.py:50-60`). The three actual fold training sets have 115, 117 and 120 rows; each sums to 0.5 safe and 0.5 disruptive weight using `conditional_forecast_20261023/learning.py:10-20`. All 17 disruptive shots contribute a positive row. The three safe shots are still the independent safe sampling units, not their 105 windows.

8. **Interpret controls as conditional ablations.** The reverse control correctly flips five 46-feature blocks, not a purported contiguous 115-means/115-fractions layout (`teaching.py:27-34`; `learning.py:46-47`). The train-fold mean at `prepare.py:225` uses **all** contexts of each fit shot, including early-disruptive rows, although those rows are not used in the supervised loss; it uses no held-shot contexts. `prepare.py:88-93` norm-matches controls using the real action. In particular the risk-axis sign is `sign(real · risk)`: it inherits both magnitude and one sign bit from the real action. It is a real-conditioned projection, not an independent feedback-free policy. Zero control vectors remain zero, but `F.cosine_similarity` at `prepare.py:99-102` returns 0 for a zero vector; such a value is undefined as a direction and should not be read as orthogonality.
