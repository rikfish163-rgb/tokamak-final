# 炮内更新为何无效：补全梯度路径的完整360炮消融

日期：2026-10-29。结论：**本候选未取得独立炮内预警收益，不晋升主线。** 原J-TEXT基模和旧结果保留。

## 1. 本轮属于哪条路线

这是当前重构分支的“J-TEXT固定基模→EAST流内首20炮冷启动→后续炮内适应”，不是旧V3C，也不使用support110。源分类模型、风险头、阈值及炮序与上一轮内部补全实验一致。没有训练J-TEXT在线分支，没有加入炮间更新或报警参数调整。

上一轮完整360各组均125个及时预警、32个误报。正常顺序与反序反馈的风险变化几乎一致，不能据此认为更新学到了有助于预警的时间演化。本轮先拆解实际梯度，再用整流实验检验一个明确改动：**不再同时推动补全预测和完整表示两侧。**

## 2. 相同损失数值，为什么会有不同更新方向

记临时参数为a；h(a)是完整的已观测窗口表示，h_m(a)是遮挡窗口表示，R为固定的源域补全器。原损失为：

\[
L=\operatorname{mean}_{\mathrm{valid}}\,[R(h_m(a))-h(a)]^2.
\]

原模型权重不变，但a会影响两条计算路径。因此损失下降有两种途径：让补全预测更接近目标，或者让目标表示向补全预测移动。后者不自动等于错误；是否有用必须实测。

本轮两种单路径更新：

\[
L_{\mathrm{预测侧}}=\operatorname{mean}_{\mathrm{valid}}[R(h_m(a))-\operatorname{stopgrad}(h(a))]^2,
\]
\[
L_{\mathrm{目标侧}}=\operatorname{mean}_{\mathrm{valid}}[\operatorname{stopgrad}(R(h_m(a)))-h(a)]^2.
\]

stopgrad不改变前向数值，只阻断当前步该侧的求导；下一步仍重新计算表示。因此这两项前向损失相同，梯度不同，其梯度之和还原原始双路径梯度。不能把stopgrad说成固定了一个跨时刻不变的真实目标。

## 3. 先测梯度，而不是猜测“没有更新”

对冷启动之后全部340炮，每炮选最多4个不同的完整128点窗口，先计算梯度，再读取结局做事后分组。共有1358个窗口；79649炮只有375个采样点，按实际情况取127、255两个端点，没有删炮或复制窗口。

每个诊断窗口的临时参数从零开始。这是局部梯度诊断，不是积累了历史更新的在线成绩；文件长度用于离线等间隔取样，不是线上选择窗口的依据。

同时将原表示误差精确拆为：时间块共同偏差、各块相对共同偏差的变化、CLS汇总误差。三者共用原分母，相加等于原损失。

主要结果：

|诊断量|1358窗口中位数|含义|
|---|---:|---|
|目标侧沿总梯度方向的投影贡献|0.942538|总方向主要来自完整表示侧，不是94%的损失，也不是94%的物理信息|
|预测侧沿总梯度方向的投影贡献|0.057462|补全预测侧对原更新方向的贡献较小|
|预测侧与目标侧梯度余弦|0.045992|不能把总体问题简化为两侧普遍反向抵消|
|时间变化项的正序/反序梯度余弦|0.999868|单独扣掉共同背景仍对该错配操作不敏感|

共同偏差和时间变化项沿总梯度方向的贡献中位数分别约0.441、0.551，CLS约0.0084。各项中位数不要求相加恰为1；逐窗口的精确分解已测试和复核。**原先“主要只是背景误差”的猜测不够准确，真实问题是不同项也在推动很相似的适应方向。**

## 4. 为什么不能只看漏报炮风险是否提高

按严格lead>30ms且≤125ms筛选，诊断包含115个危险窗口。对其中属于原cold漏报/迟报炮的34个窗口，预测侧单独更新的一阶方向使28个窗口风险上升，目标侧仅4个。看似值得尝试。

但安全炮的708个诊断窗口中，预测侧也使479个窗口风险上升。因此它可能只是更普遍地抬高风险。上述数值是一阶logit导数的符号，不是已经执行累计更新后的概率变化，也不是28个炮被救回；结局分组只用于事后解释，未进入在线更新选择。

## 5. 完整360的固定实验合同

- 同一180破裂+180安全测试身份集合，已用于方法开发，不是独立确认集。
- 首20炮为17破裂、3安全，均计入总成绩；这些炮不是20个安全炮。
- 同一按起始电流/磁场代理固定的离线排序。代理排序不等于已测得实际破裂危害。
- 同一首20炮密度数值映射及内部冷启动算子，不预用额外EAST标签。
- 阈值固定0.7258946895599365；首次越阈计报警；EAST及时预警严格lead>30ms，超过3000ms单列。
- 临时状态仍为输入嵌入的64个gain和64个bias坐标，每炮清零、炮后丢弃。
- 每128个已到达采样点先预测，再做一次归一化梯度更新，步长0.05、半径1；只影响后续点。
- 源编码器、风险头和源补全器权重冻结，不添加最终分数修正。
- 整炮曲线封存后才揭示真实结局；测试覆盖未来值改变不影响既往输出、跨炮状态重置、短记录正常预测。

旧双路径组直接复用已封存且校验过的曲线，不重复运行后冒充一个独立实验。新运行三组在同一前向批处理中配对。

本次完整流耗时272.49秒，RTX5070 Laptop、rl_env CUDA；这是离线回放总耗时，不是最坏在线延迟认证。

## 8. 本轮决定和下一步边界

1. 不把这次stop-gradient改动合并进成功主线，不做炮间或报警调整掩盖失败。
2. 停止在这一补全目标上继续靠换求导路径或扫学习率寻找“好数字”。三条路径及错配对照已经给出直接证据。
3. 下一个辅助任务首先必须在源域区分真实多通道时间关系与保持数值分布的重排对照；同时检查它是否帮助识别危险演化，不能只降低补全误差。顺序判别本身也可能利用缺失模式或位置捷径，需均值、可用性和重排对照。
4. 保留已达标J-TEXT分类基模；辅助任务是否值得接入炮内更新，仍需固定起点完整EAST流验证。不能因为局部梯度方向好看就跳过整流，也不能声称已学到新物理规律。
