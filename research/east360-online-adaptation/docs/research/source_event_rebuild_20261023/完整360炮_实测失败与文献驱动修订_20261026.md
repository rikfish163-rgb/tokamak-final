# 完整360炮：本轮结果未达标，失败位置已分开

实验：`lifecycle_stream360_v3_20261026`，本机rl_env CUDA，seed131，约719.87秒。
数据：固定180破裂＋180安全，按起始100ms的电流/磁场代理排序。
前20炮冷启动计入主结果；第一炮前没有EAST训练或流外标注。
源阈值固定0.7258946895599365；报警为首次过阈值，及时要求严格lead>30ms。
所有结果均为开发性诊断，不是独立未来验证。

**裁决：当前方案失败。** 不能因为FPR变低而宣称炮内有效；它既没有独立收益，组合后还比同持久模型关闭炮内差1个及时TP。不是旧V3C实验，也不能与过去流外准备20炮、重新校准过阈值的结果混用。

超过3秒的过早报警分别为：source33，aligned17，cold/intra17，inter/both4。它们已按当前合同计入及时TP，但必须单独披露。

## 2. 哪一步具体出了问题

### 2.1 单通道统计对齐解释了很多误报，但不是充分对齐

仅将 `ne_nG` 乘以0.0003150853，便减少68个误报，没有新增误报；与此同时救回1个、损失27个及时破裂报警，净减少26TP。这里改变的是统计尺度，不是经过单位认证的密度值。不能据此证明“原误报都是坏数据”，也不能认为其他22维已经跨装置等价。

### 2.2 “20炮”不是一个具有普适性的样本量

这个固定低代理前缀实际有17破裂、3安全。只靠3炮安全轨迹，未必能覆盖后续180安全炮的工况变化。该前缀不是按结果挑选的，也没有事后换掉。文献的20炮、10破裂＋10安全设置与这里不等价。

第一阶段本身只有6TP、1FP；全部计入360炮结果，未在主分数中删除。

### 2.3 炮内更新发生了，但没有形成有效纠错

340个适应炮共执行178235次成熟诊断目标写入；不是updates=0。
仅炮内相对冷启动冻结模型，逐炮TP/FP没有任何翻转；反序对照也相同。
每炮原始预测曲线的最大概率改变量中位数约0.00242、最大约0.03152：并非数值严格不变，但改动没有带来及时报警收益。

组合模型相对自身关闭炮内的影子模型，只损失了94258这一炮及时报警，没有救回其他炮。逐炮列表见独立复算文件，不能只挑一个变好的时间点展示。

### 2.4 炮间更新主要降低了报警倾向，没有证明救错

340次候选更新中，inter与both各接受71次。仅炮间相对冷启动冻结模型：少16FP，但损失30TP，新增及时TP为0。
仅炮间候选中，历史安全损失检查失败202次、历史破裂检查失败72次、源事件检查失败16次；一个候选可同时违反多项，次数不可相加当作拒绝总数。

这说明“过去若干窗口的平均BCE不升”不保证“未来炮的及时报警不减少”。当前检查只覆盖最近8炮和源事件片段，不是独立保护集。现有证据支持目标与部署评价之间存在错位，尚不能仅凭这些计数确定唯一成因。

### 2.5 分数尺度漂移与识别能力必须分开诊断

仅炮间方法在事后FPR≤0.20扫描时，TPR可达0.7722（阈值约0.1636），不同于部署阈值下的0.5000。这提示分数尺度也明显变化，不能把全部下降归因于表示彻底失效。

但该阈值使用了全流结局选择，**没有部署、不是在线增益，更不能拿来通过本轮验收**。炮内开关在这个工作点仍没有独立TPR收益。FPR≤0.10、0.15、0.20的完整诊断在audit文件中。

## 3. 文献导向的下一步，不继续盲扫参数

依据见[跨装置与炮内适应文献核查](不止Ai_跨装置与炮内适应文献核查_20261026.md)。

1. **先把对齐做成可比较的模块。** 保留当前单通道方法作对照，比较历史标签支持的类别条件协方差目标。不能把当前未知炮的真实类别传入对齐器，也不能照搬需要原始阵列诊断的PGFE。
2. **让辅助训练与风险判断有可测联系。** 冻结合格基模，利用J-TEXT训练炮及已结束EAST炮检查辅助梯度方向和有序轨迹信息；不能只凭诊断预测误差下降选更新策略。
3. **补安全相似轨迹与长期覆盖。** 比较最近8炮、定容量长期回放、事件覆盖回放；同容量同预算。危险活动但最终恢复的轨迹是必要负例，不能把“有活动”直接定义成破裂。
4. **调整监督目标之前先核对它的炮级作用。** 历史平均BCE、历史及时报警保持与未来全流收益分别报告；不能用某个过去样本损失下降代替跨炮收益。
5. **所有候选仍完整流运行。** 相同源模型、同冷启动政策、同炮序与报警规则；先看intra，再看intra+inter。不得以本轮失败为理由改回只展示局部子集。

这些是待验证改动，不是已经完成的新实验，也不意味着文献证明它们一定有效。
