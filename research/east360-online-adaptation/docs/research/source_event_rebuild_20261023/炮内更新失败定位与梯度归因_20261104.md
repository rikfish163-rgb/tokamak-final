# EAST 炮内更新：本轮实测与失败原因定位

## Material Passport

- 日期与状态：2026-11-04；实验已完成，候选未通过，研究目标仍未达成。
- 数据：现有已结束 EAST20，8 破裂／12 安全，每炮 5 个固定开发窗口；不是独立未来验证。
- 真值：只用 HDF5 `meta/IsDisrupt` 与 `meta/DownTime`。
- 主线：合格 J-TEXT 静态模型不变，在线研究只针对 EAST；本轮无 J-TEXT 在线学习。
- 证据范围：局部神经更新、反事实反馈对照及事后梯度诊断；没有新的完整 360 炮报警成绩。

## 1. 这轮实际做了什么

本轮没有继续改报警阈值，也没有在最终风险分数后增加纠偏项。重新从合格 J-TEXT 源检查点开始，比较两种内部输入表示，各运行静态、真实反馈、时间倒序反馈、保持不变反馈四种方法，共 800 条局部预测。

原始表示保持不变。候选表示只重新分配 CIII、MNM 缺测标记在输入嵌入层中的贡献：源数据中两者与 Bt 的可用性相同，因此这一改动在共同观测或共同 padding 时为零；在 EAST 单独缺测时，它是一种待验证的外推选择。数值信号、真实可用性标记和源模型权重均不改动。Bt 在此仅作可用性参考，不使用其数值或单位。

这不是对“缺测总会导致误报”的证明。此前在 J-TEXT 测试集人为隐藏诊断后，静态表现确实变差；但源域中的敏感性不能保证某一种补救设计在 EAST 有效。这一轮正是检验该补救设计。

两种表示均使用新建、慢参数为零的适配器，没有读取旧 EAST `cold.pt` 或目标域拟合的预测头。外部诊断预测头只用过 J-TEXT 离线数据，但其方案选择已受到 EAST20 开发结果影响，不能称目标域盲选。数值尺度映射使用同一已结束20炮，明确计入准备资源。

每个窗口的流程为：在第 q−26 点的输入窗口上发出未来 25 点诊断预测；等 q−25 至 q−1 的真实信号已到达后，计算误差，更新第一 Transformer 块 FFN 中的临时 4×64 状态；只评价 q 时刻的新风险。所有窗口独立零初始化，不假称完整炮内连续状态轨迹。

## 2. 实测结果：候选不采用

表中是“更新后损失 − 同父静态损失”，先在每炮内平均，再对炮平均。负值较好。这里的损失围绕固定报警门槛衡量安全／危险判断，不是 TPR 或 FPR；30–125 ms 组只含满足及时报警要求且处于原正样本训练窗内的破裂窗口。

| 表示与真实反馈 | 安全炮 | 全部破裂窗口 | 破裂前30–125 ms |
|---|---:|---:|---:|
| 原表示＋真实反馈 | −0.000625 | +0.008090 | +0.004780 |
| 候选表示＋真实反馈 | −0.000918 | +0.008761 | +0.006666 |

候选真实反馈的安全／破裂等权平均变化为 +0.003922，倒序反馈为 +0.002577，保持不变反馈为 +0.003281。真实反馈反而更差，未通过事先写明的比较规则。原表示的真实反馈也未显示独立炮内收益。

候选表示自身的静态影响也单独核算：相对原表示，安全损失增加 0.011059，破裂损失增加 0.024678。因此不能把这次内部缺测处理当作已成功的静态修复，更不能将两种表示之间的变化冒充在线学习贡献。

全部 600 个动态更新记录都显示辅助诊断目标下降；预定的 32 个真实 FFN 插入与缓存路径的风险输出逐值相同。也就是说，这一轮失败不是没有反向传播，或缓存风险与真实神经前向对不上，而是**诊断任务的改善没有转化为破裂判断的改善**。

## 3. 为什么辅助损失下降，破裂判断却变差

对同一临时神经参数，记诊断预测误差的梯度为“诊断梯度”，及时破裂判断损失的梯度为“风险梯度”。当前更新将诊断梯度经过固定的几何预条件处理后用于减小诊断误差。

一个小更新对风险损失的影响，近似等于“风险梯度与实际参数改变量的内积”。这个数为正，表示虽然诊断拟合可能变好了，风险判断却会变差。两种梯度服务于不同任务，不能因为都经过同一个网络，就认为方向必然一致。

这次逐通道求导后，对两种表示、全部 100 个窗口共 200 个样本做了检查。一阶分析对实际损失改善／恶化方向的判断 **200／200 一致**。原表示中，全部破裂窗口的实际平均恶化为 0.008090，一阶估计为 0.008017；30–125 ms 组分别为 0.004780 和 0.004618。这支持当前更新方向失配的解释，但不是对任意更新幅度都成立的保证。

例如 71304 炮、提前100 ms的窗口，真实更新使损失增加 0.084535，一阶估计增加 0.082821。69854 炮、提前59.6 ms的窗口，实际增加 0.010399，估计增加 0.010881。不是只根据两张风险曲线猜测原因，而是把实际参数改动与后续风险变化联系起来。

这一判断与原始 TTT 文献的理论边界相符：Sun 等在特定光滑、凸性和梯度界假设下分析了辅助任务梯度与主任务梯度的关系。这里的 Transformer 不满足其完整理论前提，因此仅借鉴梯度方向检查，不能引用该定理保证我们的模型成功。[Sun 等，ICML 2020，§2、§4](https://proceedings.mlr.press/v119/sun20b/sun20b.pdf)

## 4. 哪些通道的辅助任务在影响更新

下表是原表示、30–125 ms 破裂窗口中的平均一阶损失贡献。正值表示该通道对应的辅助梯度在本次更新中推向较差判断，负值表示推向较好判断。各通道共享相同更新几何和整体步长缩放。

| 本次平均推向较差判断 | 一阶贡献 | 本次平均推向较好判断 | 一阶贡献 |
|---|---:|---|---:|
| dx_a | +0.001289 | Z_proxy | −0.001316 |
| qa_proxy | +0.001092 | xuv_var | −0.001114 |
| sxr_kurt | +0.001071 | Mir_avg_fre | −0.000609 |
| v_loop | +0.001037 | n=1 amplitude | −0.000604 |
| dy_a | +0.000844 | ip | −0.000416 |

**不能据此删除“正贡献”通道，更不能说这些物理量不重要。** 这是当前模型、当前辅助目标、当前窗口和当前参数方向的数学分解，不是信号对真实破裂的因果作用。位置、回路电压、辐射形状既可能反映正常工况改变，也可能参与危险演化；现在的问题是模型还不会在这两类情况下分别利用它们。qa_proxy 等派生量的原始物理单位仍未独立标定。

首次分解运行在第50个样本之后因数值一致性检查停止：逐通道 float32 反向归约的和，与整项损失反向归约略有差异，逆几何运算放大了该差异。本轮没有直接放宽容差，而是增加一个单独的“浮点归约残差”项，用 float64 分解并按真实整体梯度缩放。第二次完成全部200个样本；残差对单个样本的一阶损失影响最大约 1.95×10⁻⁷，远小于主要失败例子的变化。第一轮失败目录保留。

## 5. 能否仅靠一组固定通道权重解决

做了一个明确标为事后分析的容量检查：允许已知20炮全部结局，寻找一组非负通道权重，权重不超过2、已观察通道平均权重为1，使安全、破裂及30–125 ms三组的一阶最差损失变化尽可能小。

在用于求权重的同一20炮上，可以得到三组均改善的线性近似，最差组为 −0.001021。但每次留出一炮、仅用另19炮求权重后，被留出炮的破裂组仍平均恶化 0.004088，30–125 ms组仍恶化 0.002526。这不是可泛化成功，也不是已完成的神经更新实验。

这里有两层限制：第一，这个留一炮分析不是按时间先后来学习，训练折包含后面的已结束炮；第二，一阶加权估计没有重演改变权重后的实际步长归一化与非线性前向。它只能说明“拟合当前已知炮”与“帮助另一炮”有差距，不能把求得权重放进在线流后直接报成绩。当前这套固定权重设计不晋级。

独立审查另发现 v1 的留出记录没有保存 query 坐标，安全炮的五个窗口只能按生成顺序对应。已保留 v1 及其原生产代码快照，在 v2 补齐100个唯一炮号／query键并重算；所有权重、折划分及数值结果逐项不变。v2 同时保存自己的生产代码快照。这是可追溯性修复，不是指标改善。

## 6. 下一轮不再重复什么，先验证什么

不继续扫描缺测嵌入分配、报警阈值或全局通道常数来补过关。此前已有条件事件头和固定梯度加权试验，也不能换名字当作新方法重跑。

下一个需要隔离的结构问题，是**更新的位置与基模原生适应接口是否一致**。当前 `Simple23.forward` 明确预留了128维临时增益／偏置，在输入 token 进入 Transformer 之前作用，并保持 CLS 与最终风险头不直接修改；本轮临时状态则插在第一块 FFN。现存源训练记录说明其采用过原生 token 更新，但原训练过程全部字节未完整封存，仍不能追认全部历史细节。

因此下一次先做原生 token 更新对照，保留同一静态基模、同一信号与时间坐标、相同源阈值，并分别核对原始与外部诊断头、绝对诊断损失与当前去时间均值损失。不同参数坐标的更新预算并不天然等价，原生整套更新规则比较后，仍需匹配实际表示改变量，才可把差异归因于更新位置。没有独立炮内收益，就不接炮间模块或报警调整掩盖失败。

另一条研究依据是 TTT layers 论文将辅助学习任务本身交给外层目标学习，而非假设任意重建目标都有效。但其原实验是序列语言建模，不能直接声称托卡马克有效；我们保留源基模，不因该论文而替换成大模型。[Sun 等，Learning to (Learn at Test Time)，§2.3](https://arxiv.org/html/2407.04620v4)

后续完整流验证必须包含首20炮的真实准备成本，逐炮封存后才揭示结局；当前开发脚本先读取整炮数组再截取因果前缀，不等于实际部署时逐块到达的 I/O。两者需在完整在线实现中明确区分。最终仍以完整流的静态、炮内、炮间、联合，以及单独报警对照回答研究问题，不以本报告的局部损失替代 TPR／FPR。
