## Exact proposed experiment, if separately authorized

**Candidate:** one shared `O` and the already-existing `c8` state, with token-dependent bases. Do not alter source model tensors, risk head, threshold, ContextMemory key/kernel/rate, or c8 write. Keep the current cold slow operator and mapping exactly as defined by the verified parent. Let `h_t[k]` be a data token after block 1 and the existing slow operation; let `B_t[k] ∈ R^(92×8)` be formed by the existing key/kernel from that token's observed eight-sample patch. Then

`h'_t[k] = h_t[k] + m_t[k] · O(B_t[k] c_t)`, for `k=0,…,15`.

Leave CLS unchanged **at the insertion point**. The frozen second block may naturally change CLS. Use the same causal `c_t` for all positions, reset it at each shot, and derive it only from matured observations. No label, DownTime, event, future signal or post-hoc oracle direction enters the current shot's update. Since `O` is bias-free, `c_t=0` produces exactly the existing cold path; test bitwise equality with identical batching, including its existing slow component. A current `c_t` rereads older positions using information available **now**; it is not the state that was available when those older tokens were first observed, and must not revise prior alarms.

This is not a free 16×64 oracle: for fixed observed bases and `O`, the stacked action is `stack_k(O B_t[k]) c_t`, with at most **eight** context degrees of freedom. The basis can vary with patch content; that variation is not evidence that it captures a nuisance or physical mechanism. Its 16-token norm can be much larger than a last-token write even when `||c_t||` is unchanged.

For a preparation-based comparison, train **only** `O` (64×92 = 5,888 weights, no bias) after the current stream's first 20 predictions are sealed and their HDF5 outcomes revealed; initialize from the same saved cold `O`, keep every other tensor fixed, and freeze `O` before shot 21. One explicit development choice is 256 Adam steps, lr `0.001`, gradient clip `1`, equal class and shot weighting; safe valid endpoints use `softplus(z)`, disruptive endpoints with strict `30 < lead ≤ 125 ms` use `softplus(-z)`, plus `1e-4 ||O−O_cold||²`. These settings are a proposed fixed pilot, **not** previously validated or a sweep. Keep the first-20 costs in full360 metrics. For a routing attribution, evaluate last-token and all-token routes with the **same O**, and include a matching-budget last-token-trained O or a frozen-O factorial; otherwise an improved learned O cannot be attributed to routing alone. Any held-prefix screen is conditional if its cold parent/map/O already saw those held shots; do not call it an independent holdout.

## Required controls and finite-window clock

1. **Off / exact legacy last / aligned last.** Off is zero context. Legacy last reproduces the archived global-patch `endpoint_corrections` path exactly. An aligned-last comparator uses the *same token-relative basis* as the new route but writes only its last data token. This separates multi-token routing from a changed patch phase.
2. **Real versus reverse feedback.** Reuse the existing c8 reverse contract: reverse the already-arrived horizon targets with mask intersection, holding key/kernel/rate and O fixed. It does **not** reverse model input patches. Match context/action norm where mathematically possible and report unsupported or zero cases; with one matured horizon reverse can equal real. This is not the separate frozen temporal-ablation experiment.
3. **Constant-context.** Freeze a single context chosen only from permitted source/ended-prefix history, with the same onset/mask schedule; retain actual token bases. Report both fixed magnitude and a norm-matched diagnostic. Norm-matching to real `||c_t||` leaks the real **magnitude** into the control and therefore tests direction, not complete independence from real feedback.
4. **Tiled delta.** At each endpoint, repeat the *same* last-token shift `u_t=O B_last c_t` across all valid data tokens. Scale the tiled array to the real multi-token shift's Frobenius norm if nonzero; otherwise retain zero and report the unmatched case. Compare to the real position-dependent bases, and separately report action norms, last-token effect and pre/post risk-logit change. Equal norm does not imply equal functional effect.

**Causality/alignment is a release blocker.** `patch_signal` partitions a shot into globally anchored groups `[8p,8p+7]`, and [endpoint_corrections](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/delayed_recurrent_memory_20261025/model.py:17) uses context index `floor(t/8)−1`. In contrast, [the risk window](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/simple_data.py:41) is right-aligned to each endpoint: token `k` spans `[t−127+8k, t−120+8k]`, left-padded when needed. They align with the global partition only when `t mod 8 = 7`. A naive global-index lookup can attach the wrong patch to a token, read beyond the finite window, or use an unfinished patch whose later samples have not arrived.

One explicit resolution is to recompute the same key/kernel features from the **exact right-aligned, observed W128 window at each endpoint**, reshaped into its 16 eight-sample patches, while retaining the original global progressive c8 write clock. Match the existing source-asinh and per-channel completeness/missingness conventions, mask padded/invalid data tokens, and never directly change CLS. A partial-but-valid token can have no channel complete for all eight samples: the key's bias and constant basis component can still make `B c` nonzero, so explicitly record that case and decide its support rule before fitting; do not silently treat it as observed full-channel evidence. This resolution changes basis phase relative to legacy last-token behavior, hence the aligned-last control above.

Before any GPU evaluation, require CPU tests of zero-context equality, unchanged frozen tensors, causal c8 reset, all eight endpoint phases, padded/short/missing windows, and prefix equivalence: the prediction, context and all bases at `t` must be identical when computed from the full array or a copy truncated at `t`; independently perturb every suffix after `t` and require no change through `t`. Test boundaries around indices 15/16, 23/24 and 126/127/128. Record which samples and masks form each basis and c8 write. First possible effect is not a guarantee of a nonzero update.

Predeclare failure if the real all-token route does not improve on the paired current cold and controls in a complete sealed stream, or if its apparent gain is explained by tiled action, constant context, phase alignment, a norm increase or earlier unscored alarms. A concrete strict development gate is FPR `≤0.20`, TP no lower and FP no higher than the **same-parent** cold, at least one strict improvement, and higher J than each of aligned-last and tiled controls. Also require a paired advantage over reverse and constant-context before attributing gain to the current context; equal or unsupported controls are inconclusive for that mechanism. Report all rescued/lost D, removed/new FP, strict first-alarm lead `>30 ms`, alarms `>3000 ms`, onset timing, context/action/logit magnitudes and unsupported cases. A repeatedly used balanced 360 development list is not independent future confirmation; failure of this one fixed routing is not a proof that all multi-token mechanisms fail.
