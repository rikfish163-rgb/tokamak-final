# 炮内写入位置的等动作对照：输入 token 与两层之间

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: run and verify
- Origin Date: 2026-11-06
- Verification Status: specified before testing any new internal position
- Version Label: patch_utility_site_v1

跨视图训练将单动作有益原炮从 10 增加到 39，真实模型仍不在任何
可救迟报窗口把有益动作排第一。停止调同一选择器。先回答更基础的
问题：**同一个可因果生成的残差张量，写在首层之前还是首层之后，
会改变多少真正可救的首报，又会引入多少潜在误报？**

1. 只用三个既有 J-TEXT TRAIN 封存视图。对每视图完整纳入所有
   静态迟报的破裂炮，以及既有输入动作菜单下有任一正或负硬
   单写入效用的安全炮。此为按既有结局取样的容量诊断，不是
   代表总体的在线回放；未纳入的安全炮不用于声称 FPR。
2. 对同一炮、同一释放点、同一轴及符号，复用已封存的 64 维
   方向和相邻 patch 残差。两处均只写有效数据 token，CLS
   不直接写，维度、时钟、32 点作用窗、源阈值和基模固定。
   A 在输入 token；B 在首层 attention+FFN 完整之后、第二层
   之前。比较的是同一方向族的作用位置，不宣称穷尽 B 的能力。
3. 同一正负动作对在两个位置共享精确尺度，从
   1、1/2、1/4、1/8、1/16 中选最大可行值。要求两个位置、
   两个符号在三个已到达保护点的实际 logit 变化均 ≤.10，
   采用已有数值安全余量。均不满足则同弃权。任何可行
   尺度、状态和波形都不由当前或未来结局决定。两个位置
   的注入张量逐值相同，后续传播差异由冻结网络产生。
4. 两个位置各有完整同锚点恒偏移动作库。真实前向计算
   未来 32 点的响应并封存，再计分。以原 HDF5 结局、原
   首报严格 >10 ms 判断。报告每视图的单写入迟报救回、
   原误报消除、新增误报**可达数**，以及去重原炮和输入／
   中层的各自独有病例。另报只有多段写入才可消的误报、
   共享限幅与任一位置单独可行的差；不训练选择器。

只在中层至少有一个新增的、等锚点恒偏移不能复现的迟报
救回时，才考虑针对中层重新生成物理方向。即使有新增，
潜在误报一并报告，不将事后菜单容量解释成在线效果。
