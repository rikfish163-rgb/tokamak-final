# 原生 token 适应接口：同一 EAST20 上的开发对照

2026-11-04。此方案在本轮原生接口结果产生前写明；EAST20 已多次参与开发，不是独立预注册或未来验证。

## 问题与不变量

前一轮第一 FFN 的4×64临时更新改善诊断预测，却损害破裂判断。当前源 `Simple23` 另有原生128维 token 增益／偏置接口。本轮验证这套原生更新配置是否更适合已到达诊断反馈，而不是继续改变最终风险分数。

保持合格源 checkpoint、scaler、阈值、真实availability、23通道顺序和数值处理不变；不读取 EAST cold.pt、不拟合目标风险头、不用 support110。使用固定已结束20炮、原100个时间坐标与原 density_gain 数值映射，明确计为20炮准备资源。后340炮不读取。

## 具体比较

- 原生接口固定为 `base.initial_fast + delta128`，只在进入 Transformer 前改数据 token，不直接改CLS、风险头或报警器。
- 更新采用源代码原有 `FAST_STEP=.05`、半径1的 normalized_step。不是把它与FFN隐空间0.05步长视为等预算；这是整套规则对照，后续若有效仍须匹配实际表示改变量再分离更新位置因素。
- 两种诊断头：源 checkpoint 内原头；此前只用 J-TEXT 离线训练的外部 forecast_only。两者冻结，不覆盖源头。
- 两种损失：原生绝对坐标 SmoothL1；此前去掉每通道时间均值的 SmoothL1。
- 每个头／损失组合均有真实、倒序、保持反馈及静态对照；静态风险计算是同一个父模型，复制的静态记录不是独立模型或重复实验。
- 每个局部例子delta从0开始；不冒称完整炮内状态轨迹。

## 因果与评价边界

固定 `origin=q-26`，反馈目标为已成熟 `q-25…q-1` 的25点真实诊断，更新仅影响 q 的新风险。每种反馈使用同一可用性掩码。计算期间禁止读硬结局；全部神经预测封存后，才读取 HDF5 `IsDisrupt` 与 `DownTime` 评分。这个开发读入器会加载整炮再截前缀，不能称实际逐块到达I/O实现；时间坐标选择与数值映射也利用了已结束20炮资源。

局部风险损失采用与前轮相同的固定门槛 margin BCE：安全目标0，lead严格>30ms的破裂query目标1；EAST125ms训练点标签另外保留。先炮内平均、再按炮平均，分安全、全部破裂、30–125ms及更早组。局部损失不是TPR/FPR。

主候选预定为原生诊断头＋绝对损失（native_absolute_real）：安全、破裂与30–125ms组相对静态均改善超过1e−6，安全／破裂等权平均变化比同父倒序及保持反馈均低超过1e−6，才通过局部开发筛选。其他组合完整报告，不用隐藏筛选把次要发现冒充预定主结果。任何局部通过仍须完整流的逐炮对照，不能提前宣称在线收益。

## 核对

先完成原生接口CPU单元测试；主进程再做本地CUDA运行。静态q风险须与前轮原表示静态逐值相同。所有base、scaler、native head、external decoder状态与参数梯度均保持不变；只有本地delta反向求导。检查完整4配置×4反馈模式×100坐标、封存哈希、HDF5结局和评分及损失目标是否真正产生梯度。无收益不接报警调整掩盖失败。
