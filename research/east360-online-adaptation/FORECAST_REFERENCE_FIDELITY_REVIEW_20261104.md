The CLI takes `--reference`, `--design`, `--prior` and `--output`. It does not call `verify_fit_design` for the historical prior or invent a `teaching_objective`. It checks the prior's completed/protocol source-only claims, every completion-listed artifact hash, the exact decoder SHA-256 `cdde96086517cbc468a911bbb5926dde1c783b3711b0a8abc09caf0a6d2e6730`, and every archived producer hash. The pinned archived `trial.py` SHA-256 is `5eb353e131f081fb984825dc97fb1956b6d42964252a82ba17750426792a5c33`: its `forecast_only` objective uses absolute diagnostic loss plus initialization anchor; risk terms are added only to the other arms. Outcome-informed sampling and prior source VAL exposure remain part of its development history.

The reference's completion, NPZ seal, archived producer, design/source binding and frozen state digests are checked. The new comparison binds [FORECAST_ONLY_REFERENCE_PLAN_20261104.md](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/FORECAST_ONLY_REFERENCE_PLAN_20261104.md) in `comparison_plan_sha256`; the earlier fidelity plan remains independently checked against the reference. Both plans are archived and rehashed at completion. Current fidelity and seven relevant reader/model files must still match the reference's archived hashes. Source-VAL coordinates are checked against the locked archive; the new run requires the same **946 records / 145 shots / 764 complete / 182 incomplete** reference support. It will require every reread raw hash to equal both the reference and source archive, and will compare the zero-fast native source forecast with the sealed reference to `1e−6` maximum absolute tolerance.

Only `heads.forecast_only` is loaded into an independent frozen head. The new sealed NPZ contains **only** `indices` and a `forecast_only` array of shape `2 × 764 × 25 × 23`; it does not masquerade as the old four-head output. After that NPZ is sealed, future truth is reread using the existing VAL-only hash-checked reader and `future_target`. The single-head SmoothL1 calculation is cross-checked against `fidelity.score_window` on each of the **four actual old prediction columns**, not fabricated columns. For every window/view it also recomputes the old four losses and hold loss, requiring agreement within `1e−12` and the same observed count before reporting paired deltas.

The historical reference did **not** save the target mask bits. Same raw-file hashes, matching target-code hashes, reconstructed masks, observed counts and reproduced old losses provide a strong pairing check, but do not constitute a direct byte-for-byte comparison to an archived historical mask. The reader may load a whole ended shot; the model sees only the query prefix. Horizon completeness is retrospective. These are zero-fast forecasts, not adapted forecasts, alarm performance or physical-law evidence.

Outputs include per-coordinate `mean_loss`, `delta_vs_native`, `delta_vs_risk_taught` (the reference's `anticipation125` head), and `delta_vs_hold`, with window-then-shot macro summaries for overall and four strata. Incomplete horizons remain explicit and unpredicted. Source and single-head before/after state hashes, provenance, code ZIP, seal and completion manifest are recorded.
