# Time and label audit — 2026-10-31

## Bottom line

The current EAST full360 saved clocks are **internally consistent with the actual HDF5 signal attributes**: all 360 saved time arrays exactly equal `data/ip.StartTime + arange(len(data/ip))/data/ip.SampleRate`, and all 23 channels have exactly the same length, start and rate as `ip` within each shot. All 360 actual rates are exactly 1000.0 under the stored attribute; under the active code's Hz/seconds convention, 25 sample intervals from origin to maturity correspond to 25 ms. The 25 newly arrived samples themselves span 24 intervals from first to last. This is not independent proof of the original instrument's physical calibration or units.

There are two important qualification issues, neither a demonstrated failure of that saved clock:

1. `meta/StartTime` differs from signal `StartTime` for 325/360 shots, always by more than 0.1 s, up to 2.099 s. The reader correctly uses the signal attribute, not `meta/StartTime`. Metadata may refer to a different extent; its upstream meaning was not independently established. Reconstructing the current clock from the metadata start would be wrong relative to the saved signal grid.
2. The current EAST cohort deliberately uses HDF5 outcomes, which differ from the original TEST shot-list class for 18/360 shots (17 listed safe but HDF5 disruptive; 1 listed disruptive but HDF5 safe). This discrepancy was already recorded in the locked cohort manifest; it is not proof that either source is physically correct. Do not silently mix the two label authorities.

The J-TEXT checkpoint's SHA is confirmed, but the present reader and labels must not be asserted to be the historical training implementation: the source run did not record the `io23.py`, raw HDF5 or AdvancedTime file hashes, and three of its seven recorded code hashes differ from the current files. No source training, source TRAIN model re-evaluation, model inference or GPU work was performed.

## Active io23 clock and outcomes

[`io23.py:62`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:62) reads the 23 signals; [`io23.py:75`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:75) takes rate and start from `data/ip`, and [`io23.py:92`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:92) computes `times = start + arange(N)/rate` without resampling. Strict accepts `1000 ± 1e-9` Hz; EAST nominal explicitly permits `1000 ± 0.5` Hz but retains the actual rate ([`io23.py:25`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:25), [`io23.py:47`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:47)). All 360 current shots meet even the strict contract exactly; nominal tolerance was not needed for this cohort.

[`io23.py:99`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:99) reads `meta/IsDisrupt` and, only for a disruptive shot, uses finite `meta/DownTime`; the stored DownTime of a safe shot is ignored. [`io23.py:110`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:110) computes `(down-times)*1000` as ms and considers a disruptive point valid down to `-1e-6 ms`. This establishes the **code convention**: start and down on the same seconds-like scale, rate in Hz, lead/horizon in ms. For the inspected examples, `data/ip` has `StartTime` and `SampleRate` but no unit attribute; the native units and physical event-time calibration are not independently established by this audit.

Concrete example: [EAST shot 71304 HDF5](/media/hetaisheng/044A81D94A81C83E/Fuison/data/EAST/unified_hdf5/71300/71304.hdf5) has `data/ip` attributes `StartTime=3`, `SampleRate=1000`, length `3492`; `meta/StartTime=1.101`, `meta/length=5391`, `meta/time_interval=0.0010001854943424225`, `meta/IsDisrupt=1`, and `meta/DownTime=6.492999999999999`. Its saved times start at `3.0` and end at `6.491`, not at `1.101`. The full360 census found `meta/length` and `meta/time_interval` present in 195 shots and absent in 165; in those 195, length differs from the signal in 194, and interval differs from `1/rate` by more than `1e-12 s` in 122. No conclusion about why these metadata differ is implied.

## J-TEXT active label semantics and identities

[`simple_data.py:32`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/simple_data.py:32) attaches HDF5 outcome; for J-TEXT it uses [`io23.py:166`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:166): `H=max(25 ms, AdvancedTime)`; missing AdvancedTime gives `H=25 ms`. [`io23.py:143`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/io23.py:143) treats the JSON number as milliseconds. For disruptive shots a valid sample is positive at `lead <= H + 1e-6 ms`, otherwise negative; post-terminal samples past the tolerance are invalid. A safe shot has all-zero labels and all samples valid. Thus these are end-relative constructed labels, not independently established physical precursor-onset annotations; earlier negative points are not thereby proven physically safe.

Actual examples from the current files:

Applying the current reader's rule to its actual clock gives 24 positive samples; the first has lead `24.66167768371591 ms`.

## Strict >10 / >30 evaluation, and why 125 ms is different

[`fixed_test_protocol.py:13`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/fixed_test_protocol.py:13) defines strict `>10 ms` for locked J-TEXT TEST220 and strict `>30 ms` for EAST TEST360. [`simple_train.py:15`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/simple_train.py:15) picks the **first** score `>= threshold`, computes `round((DownTime-first_time)*1000, 9)`, then compares strictly; equality is not timely. It counts any alarm on a safe shot as FP. The current run obtains its fixed predictions through [`operational_transport_20261030/run.py:96`](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/operational_transport_20261030/run.py:96).

Independently recomputing the first crossing from all ten saved score curves, the 360 HDF5 outcomes and reconstructed clocks reproduced all **3,600** saved `alarm`, `lead_ms`, `timely`, and first-alarm-time records with zero discrepancies. Examples in [per_shot.json](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/probe_outputs/anchored_full360_diagnostic_v1/per_shot.json:1): cold shot `71370` has 10.2 ms, so is not timely at >30 but would meet >10; `origin__real` shot `73405` has exactly 30.0 ms after rounding and is not timely. Cold `81684` has exactly 10.0 ms and would also fail strict >10. On the identical saved cold EAST predictions, 125/180 disruptive shots satisfy >30; 17 more have `10 < lead <= 30`, so 142/180 would satisfy >10. This is a counterfactual threshold-rule count on the same saved data, **not** a new model evaluation or a cross-device performance comparison.

The current runner calls `labels_at(...,125.)` only to obtain `valid`, discarding its label (`_`) before scoring ([run:162](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/anchored_stream_20261031/run.py:162)). Its first-alarm >30 metric has **no 125 ms maximum lead**: cold shot `71304` is timely with lead `3479 ms`. A 125 ms point-label window, 25-sample feedback horizon, and strict >30-ms shot-level alarm criterion are therefore different objects and must not be conflated. The fixed test is development-exposed, not independent confirmation ([fixed_test_protocol.py:1](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/experiments/risk_aligned_online/fixed_test_protocol.py:1)).

## Source checkpoint provenance limit

The actual [source.pt](/media/hetaisheng/044A81D94A81C83E/Fuison/experiments/risk_aligned_online/runs/gradient_aligned512_20260929/source.pt) SHA-256 is `c7270c1ea3652db2e30e972d4ca9a4a2d33220a68e4a3765c8b7f5bcceeaeb02`, matching both its saved `hashes.json` and the [current protocol:392](/media/hetaisheng/044A81D94A81C83E/Fuison-intra-trajectory-20261028/probe_outputs/anchored_full360_diagnostic_v1/protocol.json:392). Its [historical protocol](/media/hetaisheng/044A81D94A81C83E/Fuison/experiments/risk_aligned_online/runs/gradient_aligned512_20260929/protocol.json:1) lists TRAIN/VAL IDs equal to the current canonical lists, parent SHA `2291666ac48203d4e50468ca5fc242648620e8599c28d436309b6e3aaef4f0ae`, seven code hashes, and `DEVELOPMENT_ONLY` evidence. The source directory contains no code snapshot or per-input/AdvancedTime hash manifest. In particular `io23.py` and the AdvancedTime file are not hashed in that protocol. The current `joint_meta.py`, `fast_direction.py`, and `simple_data.py` do **not** match the corresponding historical recorded hashes; `simple_train.py` and the other three recorded files do. The saved `training.json` also has an episode digest, which was not reproduced and does not by itself establish the full raw input or label lineage.

Accordingly, this report establishes the **current** reader's behavior and data, not the exact labels/times actually seen throughout source training or its parent chain. Restoring and checking the original hashed code, input/label snapshots, and parent provenance would be needed before making that historical claim. For the current full360 run, by contrast, the live and run-snapshot hashes of `io23.py`, `simple_data.py`, `simple_train.py`, `fixed_test_protocol.py`, and the anchored `run.py`/`stream.py` were each checked against the current protocol and all six match.

## Limits

No GPU, model execution, training, source TRAIN model re-evaluation, numerical feature/unit analysis, file deletion, commits, raw-data changes, or model/code changes. Raw HDF5 class disagreements and the physical origin/units of times require external or upstream-data adjudication; this audit cannot choose the true authority. Current saved arrays, receipt indices and hashes are checked, but the model's computations were not rerun and upstream sensor timing was not independently calibrated.
