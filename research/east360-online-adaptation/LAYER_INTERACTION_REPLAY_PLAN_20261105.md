# 双层炮内更新：整炮消融与交互损失

## Material Passport

- Origin Skill: experiment-agent
- Origin Mode: run
- Origin Date: 2026-11-05
- Verification Status: pre-execution plan
- Version Label: layer_interaction_replay_v1

问题：安全炮的风险是由某一个内部更新位置单独放大，还是由两处共同作用？
这种差异在完整曲线（不只后验最高点）上能否让误报回到 20% 上限，同时保留及时报警？

**整炮消融。** 使用已封存的 moving-peak 前20炮拟合，不重训。保持同一笔实时动作的
第一层、第二层、增益系数或偏移系数，其余置零；两个额外单层对照将保留的一层
恢复到双层动作的逐更新 L2 范数，区分“减少改动量”和“切断层间交互”。
并行重算静态和未拆分的双层同炮轨迹，要求阈值跨越逐点和旧档相同。

**等预算训练。** 从共同 history20 检查点重跑，固定已结束前20炮的 moving-peak
三轮选点；两臂使用同一初始权重、选点、Adam 步序及 36 步。每个已知安全训练窗口
按实际内部前向计算 (I=z_{11}-z_{10}-z_{01}+z_{00})，其中 (z_{ab}) 表示
只启用指定内部层更新时的原模型 logit。实验臂在原风险与动作能量损失上加入
(max(I,0)^2)，系数固定 1；对照计算同样的四个分数但系数为 0。
不向破裂训练窗口施加该项，不按后缀结局选择惩罚权重。两臂各加同范数滞后对照。
这是对安全样本正向非加性交互的软惩罚，不是安全上界。推理过程不添加后处理。

两个回放共用原源模型、前20炮输入映射、EAST HDF5 结局、同一完整360序列和阈值
0.7258946895599365。前20保持原始预测；第20炮封存并揭示后才能装载/拟合规则。
后续同炮动作只读已到达诊断信号，按炮重置。后缀标签仅在逐炮封存后用于计分，
不回流到本轮模型，不另加标签、不换集合、不调报警器。

主结果用严格 >30 ms、误报率、J，另报 30–3000 ms 及时和 >3000 ms 数量。
逐炮配对数清楚区分新救回、丢失、误报新增和消除。候选必须在 FPR≤.20 下
改善静态且胜过同幅滞后，不能用秒级过早报警替代有效收益。整炮拆分仅为机制
诊断，不按已知后缀成绩晋升。固定360是反复使用的开发流，无独立效应声明。

工作目录：本研究 worktree；执行 `layer_interaction_replay_20261105.py --mode
{mask,fit} --output <new-directory>`，使用 rl_env CUDA。各进程硬超时 360 s，
标准输出记录每25炮，期望完整360炮的逐炮封存和摘要以及独立原 HDF 复核。
